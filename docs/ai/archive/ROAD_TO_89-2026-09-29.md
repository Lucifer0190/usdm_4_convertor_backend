# Road to >89% — definition, measured baseline, and the work that gets there

**Date:** 2026-09-29 · Companion to `PROTOCOL_TO_USDM_ARCHITECTURE.md`
**Status:** a benchmark now exists (8 hand-corrected Pfizer USDMs, 1,412 reference items). Nothing below is a promise; each number is either *measured* or labelled *estimate*.

---

## 1. What "89% accurate" has to mean (so it can be checked)

`src/usdm4_assure/eval/rubric.py` is the definition, applied identically to every study:

- **Item** = one element of the reference USDM: title, sponsor, phase, protocol id, version, study type, model; each identifier; each arm and intervention; each eligibility criterion; each objective, endpoint and estimand; each epoch, visit and activity; each scheduled (visit, activity) mark; each vendor organisation.
- **Matched** = the delivered study holds an equivalent element (one-to-one, token-overlap thresholds).
- **Accuracy = matched / (reference items + spurious delivered items).** A wrong or invented item costs as much as an omission, so delivering more cannot raise the score. Recall is reported next to it.
- `spikes/run_benchmark.py` runs the pipeline on the latest protocol of each of the 8 studies and scores it. Deterministic by default (free); `--llm` turns the LLM readers on.

Two things this definition still needs from you (Section 6): **audited gold** and whether 89% is **before or after human review**.

## 2. Where we are (measured)

| Run | Scope | Accuracy | Recall |
|---|---|---:|---:|
| Before any fix (single study, older rubric) | C5091017 | 5.4% | – |
| Deterministic, all 8 studies, before the SoA reader | 8 studies, 1,412 items | **19.1%** | 25.4% |
| Deterministic, after the geometry SoA reader | 8 studies | **36.2%** | 49.0% |
| – development study (C5091017) | 1 study | **77.8%** | 89.7% |
| – the other seven studies | 7 studies | 16–36% | 20–53% |

**The gap between 77.8% and ~30% is the most important number in this report.** The readers were built while looking at one protocol, and they fit it. That is exactly what a multi-study benchmark exists to expose. To claim a number for unseen protocols, development must use a train split and be measured on studies it has never seen.

## 4. The reference is not perfect — and that caps what any score can show

Concrete cases found while diagnosing, not hypotheticals:

- **C4891024:** the reference has 4 encounters; the protocol's schedule has about 30 columns. The reference collapses cycles into buckets (the downstream team's own gap report asks for this to be expanded). Our correct, more detailed output is scored as "spurious".
- **C4891002:** the reference contains the historic "Study Lead-in" and "Phase 3" schedules from the amendment-history appendix. Reading only the current schedule lowers recall against this reference, although it is the more correct reading.
- **C4891006:** the reference lists Day -7 / Day 15 visits from the *prior* schedule while the current amendment's schedule is a reduced one.
- **All studies:** group headings ("ELIGIBILITY") are counted as activities, some activities are duplicated, and several study versions have no marks at all (C4601003 has none).

So a high score against these references can partly mean "we copied their quirks", and a low score can partly mean "we are more correct than the reference". **Only an audited gold set settles this.**

## 5. Work packages, with what each is worth (item counts are measured; gains are estimates)

| # | Package | Targets (items) | Acceptance test |
|---|---|---|---|
| **G** | **Audited gold**: SME-verified items for a train set and a held-out set, built by correcting our own output in the existing review UI (it already exports edits as labels). Freeze the held-out set. | all | reference error rate measured; held-out never used for tuning |
| **S1** | **SoA generality**: cycle-based tables, reduced/amended schedules, several tables, notes/footnote conditions, rotated and multi-row headers, tables with no rules (fallback), group rows as parent activities, continuation and "Table 2" handling | marks, activities, visits, epochs (851) | ≥85% on held-out SoA items |
| **S2** | **Independent SoA check**: frontier vision model on the header and a sample of cells (the repo's `vision` / `vision_alt` roles), plus the mechanical mark re-derivation the repo already has; disagreement → review | SoA errors | disagreement rate reported; catches reader failures |
| **O** | **Objectives/endpoints reader** for two-column, phase-split and per-population tables | endpoints, objectives, estimands (211) | ≥90% on held-out |
| **I** | **Identifiers, scalars, vendors**: synopsis label block (IND, EU CT, NCT, PIP, compound), running header, external organisations named in the text | identifiers, scalars, vendors (147) | ≥90% |
| **L** | **LLM readers for semantic fields** on the narrow windows (already built): arms, interventions, sponsor, version, estimand attributes | scalars, arms, interventions, estimands | measured with `--llm` on the 8 studies |
| **A** | **Assurance on real data**: calibrate confidence on gold; route low-confidence items to review | accuracy *after* review | risk-coverage curve on held-out |

Order: **G (start now) → S1 → O → I → L → S2 → A.** G comes first because without it every later number is measured against a moving, imperfect target.

## 6. Decisions I need from you

1. **Gold.** Who can audit protocol items (a clinical data manager)? The plan assumes about a day per study with the review UI; without an audited gold I can only report agreement with the team's references, not accuracy.
2. **Which 89%?** Pre-review (the pipeline alone) or post-review (after a human clears the flagged items)? Published state of the art is 89.0% pre-review on field extraction, so pre-review >89% would be at or beyond the best published result. Post-review >89% is realistic if the confidence ordering is good.
3. **LLM budget.** One full 8-study run with the LLM readers is an estimated **$5–10** (14 calls per study on Sonnet 5.5 / GPT-6 Sol / Opus 5.5 from the C5091017 run, plus vision for S2). It sends Pfizer protocol text to OpenRouter. May I run it, and how often?
4. **Train / held-out split.** Proposal: develop on C5091017, C4601003, C4891001, C4891002, C4891006; freeze C4891023, C4891024, C4891026 as held-out. The 30 other Pfizer studies have no USDM reference and can be used only for invariant checks (numbering, column counts) without labels.

## 7. Honest expectation (an estimate, not a measurement)

If G, S1, O, I and L land as described, I expect the **development studies to reach the mid-80s to 90%** against audited gold. For an **unseen Pfizer protocol** I would expect roughly **75–85% pre-review**, because layouts vary (the C5091017 → other-study drop above is the evidence). Reaching a *measured* >89% on held-out protocols pre-review is possible on the Pfizer template family but not yet demonstrated, and I would not promise it for other sponsors. What I can commit to is measuring it correctly and showing the number, including where it falls short.
