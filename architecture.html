The thesis

The real failure mode is silence, not error

Published systems don't mostly return wrong values — they return confident, well-formed, schema-valid studies that are quietly missing rows, visits and criteria. On long documents frontier models hold high precision while recall falls to ~50%. Nothing looks broken. In a regulated workflow that is the worst possible failure, and every mechanism below targets it.

What actually breaksOur counter-mechanism
Silent omission
~50% recall at high precision on 358-page docs; 0% valid output at 369 schema fields. Data vanishes without a trace.
→
Sharding + completeness accounting
<40 fields per call over routed windows, and every domain reconciles expected vs found counts. A gap becomes a finding, not a silent pass.
Ungrounded values
A plausible value with no real source — and model-emitted page numbers that were never in the document.
→
Mandatory verbatim quote
The model emits a quote; our code resolves it to page, character offset and bbox. A failed substring match is a hard reject. 93% vs 19% exact match, published.
Table structure destroyed
Merged cells and multilevel headers lost — and clinical SoAs routinely span 3–6 pages, which no available tool stitches correctly.
→
Specialist grid + VLM content
A 1.2B specialist beats frontier VLMs on structure; VLMs win on cell text. Split the job — plus a purpose-built multi-page stitcher.
Dishonest confidence
Reviewers can't see which fields are risky. Verbalized confidence scores 0.692 AUC — worse than logprobs, which are themselves weak.
→
Calibrated + conformally bounded
Fused multi-signal confidence (0.928 AUC published), then a conformal threshold giving a provable bound on error among auto-accepted fields.
retracted in v0.3 “2 paths @ 89% → 97–99% precision” → agreement is a feature, not a guarantee

The accuracy math, corrected. v0.2 claimed that two independent paths agreeing implies ~97–99% precision. That assumes independent errors. Measured cross-model error correlation is ρ = 0.74–0.82 — three to five times higher than human forecasters — and 48% of model mistakes replicate across families. Errors from a shared parsing stage are ρ = 1.0 across every downstream model. Unanimous agreement on a wrong answer is common, and systematically so on the hard fields. So ensemble agreement stays — as one input feature to a calibrated confidence model, never as a precision claim.

Grounding + Assurance · the moat

Three mechanisms, each earned by evidence

Candidates flow through here and come out cited, scored and triaged. These are Phase-1 core, not later niceties — and each replaces a v0.2 mechanism that the literature did not support.

L5 · Grounding

Verbatim quote, resolved in code

Every field carries a quote that our code locates in the PDF by exact substring match, then resolves to page, character offset and bbox. A miss is a hard reject. The model never emits coordinates — that is hallucination-prone and unsupported by any benchmark.

L6 · Completeness

Expected vs found, every domain

Visit count from the design section reconciled against SoA columns; arm count against cells; activity rows against footnote references. Because the dominant failure is omission, counting what should be there is as important as checking what is.

L6 · Confidence

Fused, calibrated, bounded

A fitted model over grounding-quality features, entailment, cross-model agreement and field type — 0.928 AUC published, versus 0.705 for logprobs. Then a conformal threshold: under exchangeability, error among auto-accepted fields is provably ≤ α.

Marginal, not conditional — the conformal bound holds across all fields on average, not within every field type. With ~4 protocols we can support a global bound; per-class guarantees need ~20+. We say exactly that and no more.

Safety-critical module · the risk centre

The Schedule of Activities sub-pipeline

A wrong test at a wrong time point is a protocol deviation — a GCP event. So the SoA never routes through the prose extractor. And because clinical SoAs routinely span 3–6 pages, the stitching step is custom-built: Docling does not merge cross-page tables and MinerU drops content on continuation pages — both open issues.

Stitch
Match column-header signatures across consecutive pages, detect “(continued)” cues, reconcile column counts. Hard-fail loudly rather than silently emitting two tables.
Grid
A specialist table model owns the structure. At 1.2B it beats Gemini-2.5-Pro and a 72B VLM on TEDS — structure is not a job for a generalist.
Content
A vision-LLM fills cell text against the fixed grid, per region. MLLMs win on cell content; they lose on structure. Never one model for both.
Re-derive
Mechanically re-derive the mark matrix from the PDF as an independent cross-check, then emit ScheduledActivityInstance, Timing windows and footnote Conditions.

Gated by a hand-labelled set of 30–50 real multi-page SoAs before it is trusted. The re-derivation pattern is adopted from kerfors/soa2usdm (MIT, PHUSE 2025).

Model orchestration

Frontier LLMs, accuracy-first strategy

One OpenRouter gateway, many models, roles declared in config so any model is swappable without code changes. Frontier models (Claude Sonnet 4.5, GPT-5.1, Gemini 3.1 Pro) are the default for all text-based roles. Small models (Llama-3.1-8B, Qwen, gpt-oss-20b) are not in the design — published evidence shows frontier models outperform them in every measured domain. One specialist survives this accuracy-first test: MinerU2.5 (1.2B) beats Gemini-2.5-Pro on table structure. Every OpenRouter slug below is verified live against the catalog (444 models, checked 2026-09-17).

Logprobs are never load-bearing — OpenRouter accepts the parameter but not every provider honours it. Cross-family verification only, on the uncertain subset; never let the extracting model judge its own output (self-preference bias up to +90%). If sampling for self-consistency, vote in YAML or free text then emit JSON once — JSON grammars collapse answer diversity from 41% to 64% modal share. All prompts version-controlled and hashed into the audit trail. The disk cache (Phase 0) makes re-runs free after the first pass, so cost is controlled by cache hits and verification on the uncertain subset, not by downgrading to smaller models.

Build strategy

Assemble on the ecosystem — add what no one has

Mature open-source bases give us the plumbing and, crucially, the ground truth on day one — so our effort goes into the Grounding and Assurance layers that constitute the differentiator.

Plumbing base

data4knowledge usdm4

Pydantic USDM 4.0 model, the Assembler, the d4k rule library, offline controlled terminology, the CORE facade. GPL-3.0 — fine for internal use, recorded as a deliberate decision.

Ground truth

usdm_data · ~20 studies

Real studies mapped to USDM and CORE-validated, each traceable to a public NCT protocol PDF. This is our eval seed — it replaces hand-labelling four local PDFs from scratch.

What we add

Grounding + Assurance

Verbatim citation with code-resolved coordinates, completeness accounting, fused calibrated confidence, a conformal bound, and a Part 11 audit trail. No published system ships these together.

Also adopted: kerfors/soa2usdm (MIT, PHUSE 2025) for the SoA mark-matrix re-derivation pattern — permissively licensed, so its approach can be used directly rather than merely imitated.

Delivery plan

Phased, and de-risked by re-measurement

Dockerized from day one: the PoC runs locally via docker compose; the same image deploys anywhere.

Phases 1–3 · ~6.5 weeks

Grounded spine on real protocols

  • Substrate + verbatim-quote grounding + Part 11 audit
  • Backbone domains, sharded schemas, three gates
  • Multi-page SoA stitcher + specialist grid + VLM content
  • Mechanical re-derivation as an independent cross-check
  • Fingerprint, section graph, prohibited scopes
  • Completeness accounting across every domain
Phases 4–7 · ~8 weeks

Measured, certified, published

  • Fused confidence + recalibration + conformal bound
  • Risk-coverage curve — the real product metric
  • Review UI, sign-off, post-edit-distance telemetry
  • Estimands, amendments, sites (weakest published category)
  • Full CORE run on real protocols
  • A reproducible scoreboard — no vendor publishes one
Phase 0 · first move · 2–3 days

Re-measure the foundation before anything leans on it

  1. Re-run the assembler over the corpus on the pinned usdm4 SHA. The “0 of 235 protocols assembled” figure that shaped our risk posture is stale — the vendored source already fixes two of the bugs its own findings doc lists as open.
  2. Pull data4knowledge/usdm_data and confirm how many studies give usable PDF → USDM eval pairs.
  3. Check whether the three dated Clinical Protocol - 0 (*).pdf files are one study's amendment chain — if so, that is a free fixture, and the eval set is “2 studies / 4 documents,” which changes how we talk about generalisation.
  4. Stand up CI with the sprawl guardrails: no empty packages, no files over 400 lines, no hard-coded machine paths, no field without evidence.
Green light from Phase 0 = the design rests on measured reality rather than on a number nobody has re-checked. It costs days, not weeks — and how much we lean on the Assembler versus usdm4.builder depends entirely on that one number.
